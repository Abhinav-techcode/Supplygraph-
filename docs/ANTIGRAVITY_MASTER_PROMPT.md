# 2. What was found wrong (evidence-based audit)
1. **Twin was volatile**: `PostgresDigitalTwinRepositoryAdapter` kept state in a JVM map and persisted only (workspace, version); V2 tables (`supply_chain_nodes`, `transportation_lanes`, `materials`, `bom_entries`, `inventory_*`) were unused; no way to load or edit a supply chain; the Phase 7 import service never touched the twin.
2. **Graph UI was fictional**: `DigitalTwinNetworkGraphComponent` and `DigitalTwinGraphExplorerView` used hard-coded 17 nodes/18 lanes, constant disrupted flags, fake "ConcurGuard state", hard-coded alert text, labelled "LIVE".
3. **Graph model lacks**: material-supply edges, BOM-aware propagation, true single-point-of-failure analysis (current "single source" is a heuristic), tiered impact to products/customers.
4. **Agents are stubs**: the eight agents in `supplygraph-adapter-ai` return constant `AgentProposal`s (fixed confidence/risk/evidence), ignore tool results, and `AgenticRecoveryOrchestrator` is never called by any view/service. Agent History showed 4 hard-coded rows.
5. **Recommendations were canned**: `generateAlternativePlans` returned three fixed templates (Alpha/Beta/Gamma) with constant costs; ConcurGuard received intents with no resource/capacity claims, so most detectors had nothing to evaluate; `OptimizationWorkspaceView` built candidates from literals; Home text named yet another set of options.
6. **Fabricated KPIs**: Executive cockpit (87.4/100, $4.2M), supplier OTIF/lead-time constants labelled "measured" from non-existent ERP/WMS sources, performance dashboards, persona workspaces, benchmark cards, CSRD "100%", a false "Phase 1-15 maturity checklist".
7. **Duplicate sources of truth**: two workspace ids (`WS-AUTO-01` vs `"default-workspace"`, ~25 literals), three copies of the topology, four sets of recovery options. Symptom: Home showed 2 active disruptions, Executive page 0, global search for a known facility returned nothing.
8. **Phases 11-15 are islands**: planning, sustainability, collaboration, platform administration reference none of the twin/graph/BOM/inventory/events/execution.
9. **Execution outcomes do not reach the twin**: verified Phase 10 evidence emits `RECOVERY_ACTION_COMPLETED` operational events that no monitoring rule consumes; the twin is never mutated; nothing "learns".
10. **Security**: no authentication (UI principal is a configured operator + demo role switcher); `WorkspaceAccessGuard`/permissions enforced only in Phase 9/10, audit, provenance and user-management services (~10 classes). Phases 4-8 and 11-15 services enforce nothing, including "Enterprise Platform" admin/API-key/backup features.
11. **UX**: ~50 top-level menu entries mirroring modules/phases; two "command centres"; empty first screens; raw enum states; Vaadin dev-mode banner; wide tables hiding action buttons; global search limited; no guided incident flow.
12. **Build/env**: JDK 26 incompatibility; Vaadin theme folder was missing (UI returned HTTP 500 on a clean checkout, now fixed); tests mostly validated modules in isolation, which is why 443 tests coexisted with the above.
