# SupplyGraph — Final Gap Register

**Audit Date:** 2026-11-18  
**Baseline Commit:** `0463c2c`  
**Classification:** Severity-ranked defects, omissions, and architecture misalignments to be resolved during the Master Product Completion Mission.

---

## 1. Priority 0 (P0) — Mission-Critical & Blocker Defects

| Gap ID | Subsystem | Description | Impact | Target Remediation |
|---|---|---|---|---|
| **GAP-P0-01** | Digital Twin | Port nodes are modeled as `Warehouse` and lack distinct modal capabilities. Inbound/outbound transportation lane costs lack explicit units (freight vs weight-based). | Distorts network optimization and routing costs; inaccurate representation. | Enhance node hierarchy with proper `LogisticsHub` (with intermodal ports) and explicit lane cost semantics (`costPerShipment`, `costPerKg`). |
| **GAP-P0-02** | Digital Twin | No automated or interactive supply-chain import exists. Seeding happens unconditionally at boot in `DemoDataInitializer`. | Users cannot import their own supply-chain network, BOM, or inventory. | Build `SupplyChainImportService` supporting CSV & JSON imports with transaction rollback; add explicit "Load Sample Supply Chain" button; guard startup seeding with `@Profile("!prod")`. |
| **GAP-P0-03** | Impact Analysis | Disruption impact analysis only performs node reachability; does not explode BOM down to finished products, assembly lines, or customer delivery orders. | Users cannot answer "Which products and customer shipments are impacted?". | Implement BOM-aware recursive traversal in `ImpactAnalysisApplicationService`; compute inventory Time-to-Survive (TTS) from consumption rates. |
| **GAP-P0-04** | ConcurGuard | Recovery alternatives generated by `RecoveryOptionDeriver` submit empty/zero claims to ConcurGuard conflict detectors. | ConcurGuard detectors never evaluate real resource, capacity, or time-window contentions in the live path. | Extract concrete `ResourceClaim`, `QuantityClaim`, `CapacityClaim`, and `TimeWindowClaim` from candidate action plans and feed them to `ConcurGuardEngine`. |
| **GAP-P0-05** | Agentic AI | The 8 specialist agents in `supplygraph-adapter-ai` return hardcoded static strings and proposals. `AgenticRecoveryOrchestrator` is not invoked. | "Agentic supply-chain intelligence" claim is unfulfilled; static stub output. | Rebuild the 8 agents to accept live twin and disruption context via bounded application tools (`TwinContextTool`, `ImpactEvidenceTool`), invoking Spring AI / deterministic fallback. |
| **GAP-P0-06** | Execution | Verified execution completion (`RECOVERY_ACTION_COMPLETED`) does not mutate twin inventory, capacity, or lane status. | The digital twin remains disconnected from physical reality after recovery action execution. | Subscribe to execution outcome events; mutate `TwinGraphStore` and `InventoryLedger` upon verified non-simulated execution. |
| **GAP-P0-07** | Security | Authentication relies on a demo session attribute filter (`UiPrincipalFilter`). Server-side authorization (`WorkspaceAccessGuard`) is missing on Phase 4–8 and 11–15 services. | Insecure; allows unauthenticated access and potential cross-tenant IDOR violations in production. | Configure Spring Security; enforce `WorkspaceAccessGuard` and role permissions across all public application service methods. |
| **GAP-P0-08** | UI / UX | Navigation is a flat 50+ item drawer without logical grouping. No unified incident recovery workspace exists. | Overwhelming user experience; users cannot complete the core signal-to-outcome journey smoothly. | Restructure navigation into 9 primary operational areas; implement the single **Guided Incident Workspace** (`IncidentWorkspaceView`) with a multi-step stepper. |

## 2. Priority 1 (P1) — Enterprise Architecture & Integrity Gaps

| Gap ID | Subsystem | Description | Impact | Target Remediation |
|---|---|---|---|---|
| **GAP-P1-01** | Graph UI | Network graph component lacks interactive pan, zoom, path tracing, and node search. | Difficult to inspect larger networks (>25 nodes). | Enhance `DigitalTwinNetworkGraphComponent` with viewport controls, interactive search, and affected-path highlighting. |
| **GAP-P1-02** | Optimization | `OptimizationWorkspaceView` and candidate generators use static candidate arrays instead of querying twin state. | Optimizer solutions do not adapt to imported supply chain changes. | Bind `OptimizationApplicationService` directly to twin graph nodes, capacities, and active disruption constraints. |
| **GAP-P1-03** | Planning (Phase 11) | Planning views (MEIO, Safety Stock, Reorder) use isolated repositories instead of reading twin inventory/BOM. | Disconnected planning from actual twin reality. | Feed digital twin demand, inventory, and BOM into planning calculation services. |
| **GAP-P1-04** | Sustainability (Phase 12) | Carbon emission calculations use hard-coded mock emission factors instead of lane transportation modes and distances. | Sustainability dashboards show inaccurate emissions. | Calculate Scope 1, 2, and 3 emissions dynamically based on transport lane mode, distance, and shipment volume; distinguish measured vs estimated. |
| **GAP-P1-05** | Collaboration (Phase 13) | Supplier capacity confirmations and quotations do not update core twin capacity calendars. | Supplier portal actions have no operational effect on replanning. | Propagate approved supplier commitments into digital twin capacity calendars. |
| **GAP-P1-06** | DevOps / Prod | No production Spring Boot profile, containerization, or deployment configuration exists. | Cannot deploy to cloud environments (Railway, Render, AWS, Fly.io). | Create `application-prod.yml`, production multi-stage Dockerfile, docker-compose, and deployment documentation. |
